# 0.5.0 诗歌剧、句首与句尾杂音

日期：2026-11-15。用户要求安装 `诗歌剧.zip`、新增“赛马娘”分类，并改进长句尾部滋滋声、偶发吞音与切角色杂音。后续补充为“持续滋滋更多，短促爆音也有”。

## 安装与界面

包内只有一对模型文件和 macOS 元数据，未运行附带脚本：

- `uma-Matikane_Tannhauser.pth`：RVC v2、F0 模型、48 kHz，109 个嵌入槽，使用说话人 0。
- `added_IVF1310_Flat_nprobe_1_uma-Matikane_Tannhauser_v2.index`：768 维、51,121 向量。

以 `torch.load(weights_only=True)` 检查并用既有固定版本 RVC 导出 ONNX，通过一秒 CPU 推理检查。ID 为 `tannhauser`，显示“诗歌剧”，分类“赛马娘”。模型、索引与图校验见 `installed-rvc-models.json`，大文件留在 `models/local-rvc/`，没有上传用户的 ZIP / 权重。

头像和约 3 秒语音来自 [Cygames 官方角色页](https://umamusume.jp/character/matikanetannhauser)，原始 URL 和 SHA-256 在 `assets/tannhauser-source.json` 与 `assets/references/sources.json`。按这段短语音的基频中位数，将初始自动目标定为 417.4 Hz；沿用用户要求的自动再 +4。这不是训练数据统计，也未证明最佳听感。

API 角色选项由已安装注册表产生，导入器支持合法的新 ID 和显示名，图、索引缓存可容纳四个及更多角色，避免第四个角色反复挤掉前一个。未安装的额外角色不在接口 / 分类中显示。

## 处理改动

- 输入采用连续、带状态的 48 Hz 高通，参考上游 RVC 对低频的预处理思路；没有对每个窗口独立滤波，以免接缝状态重置。[固定上游实现](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/d60cd3d009b7e438f92f8624fa89b710d10c6a39/infer/modules/vc/pipeline.py)。
- 只在语音活动之外估计 GTCRN 残余背景能量，输出门控的底线和满增益门槛随之变化，避免低音量尾音后的残余噪声继续驱动可听输出。没有混入原始有声波形。
- 低置信度句首达到 .20、且能量超过估计背景功率四倍时可以提前开门；普通开启 .35、关闭 .12 的路径和既有前瞻保留。
- 切角色会终止旧实时会话：20 ms 淡出，等待原生音频队列实际播放完，再丢弃旧 FIFO / 关闭麦克风、输出、WebSocket；等旧线程退出和 250 ms 设备间隔后用新角色创建新的状态。不会只改正在运行的模型 ID。
- VB-CABLE 播放目标缓冲 .24 → .32 秒，为偶发回包超过 120 ms 留余量；包长仍 120 ms，原生设备请求延迟仍 .02 秒（实测报告 .03）。缓存目标增加 80 ms，实际本机链路延迟以下表为准。

## 离线边界与底噪对照

使用回归集 `m2.wav` 合成男声：长句为同句连读三次、最后 .4 秒渐弱，前后有固定种子的风扇谐波 / 底噪；轻声测试将前 .6 秒缩到 30%。120 ms 包、强度 100%、自动再 +4。原三声线的轻声错字合计 **8/66 → 6/66**；每位仅 22 字，SenseVoice 会出错，改善不能泛化为“吃字已消失”。

这组离线长句修改前后，标记句后的尾段与长停顿均为零，**未完整复现用户持续滋滋声**，因此不宣称门控已消除全部问题。诗歌剧离线对照的两侧都使用安装初期的 300 Hz 目标；最终 417.4 Hz 的校准在实际通路、预热和界面检查中另行验证。

独立风扇启动会继续误触发：整段输出 RMS，灯 .00815 → .00755，塔菲 .00891 → .00796，爱音 .01088 → .01238，爱音略退化。键盘独立测试前后三声线都输出零。以上是人工合成背景，不代表用户真实房间。

## 实际 VB-CABLE 长句

用户已在 Discord 静音，原实时窗口停止后测试。输入由文件按 48 kHz / 20 ms 喂入，转换后送 CABLE Input，同时从 CABLE Output 以 48 kHz 独立录回；每声线约 40.8 秒。文件包含重复段和停顿，不能当真人持续讲话。

| 角色 | .24 秒缓冲：断流 / 整段相关性 | .32 秒复测：断流 / 整段相关性 | .32 秒最后有声秒相关性 | 本机延迟 |
| --- | --- | --- | --- | --- |
| 灯 | 1 / .44647 | 0 / 1.00000 | 1.00000 | .689 s |
| 塔菲 | 0 / 1.00000 | 0 / 1.00000 | 1.00000 | .664 s |
| 爱音 | 0 / .82339 | 0 / 1.00000 | 1.00000 | .662 s |
| 诗歌剧 | 0 / .94304 | 0 / 1.00000 | 1.00000 | .672 s |

第一轮灯有六个附近的回包约 135～182 ms，超过 120 ms 供给间隔，FIFO 一度断流。另有计数为零但波形不一致的案例，保留为失败证据，没有当作无损音频。增大缓冲后的复测未再出现；推理负载会波动，没有锁定全部异常的唯一根因，也没有完成小时级真人通话验证。延迟不含手机 / WO Mic 与 Discord。

驱动面板核对输入、输出和 Internal SR 均为 48 kHz；本次未修改驱动参数。面板累计错误不能直接归到这轮测试。[VB-CABLE 官方手册](https://vb-audio.com/Cable/VBCABLE_ReferenceManual.pdf)说明了格式、缓冲和统计含义。

## 回归与使用

- 真 GUI / 后端 / 设备自检：**85 通过、0 失败、1 跳过**（不另起第二后端）。包含“赛马娘”分类、诗歌剧原声 / 自动再 +4、实时切至诗歌剧时淡出和释放旧流、自动刷新后的实际 CABLE Output 回录。
- 37 项单元测试通过：17 项实时刷新 / 停止竞态，9 项语音门控，2 项播放淡出，2 项额外角色注册，6 项音高，1 项流式样本守恒。
- 四声线共八份当前示例已在 `assets/previews/` 重生成；清单记录 0.5.0、自动再 +4 和校验值。仍是合成中文、200 ms 文件路径，不代表实时延迟或用户原声。

可用 `.venv/Scripts/python.exe tools/eval/check_phrase_edges.py --output .run/edges-check` 重跑离线边界检查。设备测试需要先静音 Discord，再运行 `tools/eval/loopback.py`，使用 `--packet-ms 120 --pitch-preset auto4 --input-rate 48000`。数据在 `evaluations/phrase-edges-0.5.0.json`，界面自检在 `evaluations/selfcheck-0.5.0.log`。

最终仍需用户听实际通话的句首、轻声、长句尾部和切角色。任何自动重开 / 角色切换都包含物理设备关闭的间断，在该间断里开始说话仍可能丢字。
