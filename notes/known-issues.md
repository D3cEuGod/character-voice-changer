# 已知问题

## 音色与参考音

- 0.1.0 / 0.1.1 的灯和爱音参考音实际来自第三方 MiMo 合成语音。旧相似度不能代表与角色原始配音的接近程度。0.2.0 已替换参考录音、重新生成音色向量，并更正 README。
- 三位角色默认使用各自的 RVC v2。灯的权重与“凑企鹅”演唱示例由用户提供；示例录制来源未核实，原始训练数据也无法仅凭权重确认。
- 模型原自动档的目标音域为灯 320 Hz（贴近用户选定示例）、塔菲 429 Hz、爱音 310 Hz。固定移调档不使用这些目标。不同人的真实麦克风输入可能需要重新校准；导入器支持目标音域和固定半音移调。
- 角色模型仍有音色、语气和口音差距。相似度主要使用 CAM++，额外对照了不同片段；不知道这些片段是否曾出现在第三方模型的训练集，因此不能称为严格盲测，也不能当“还原百分比”。
- 0.4.2 按用户选择默认使用“自动音域再 +4”，原声 +4 预设已移除。自动再 +4 可能更尖，尤其塔菲；可在音高下拉框切回“模型默认”。对照输入是合成男声，不是用户麦克风录音；音高变化不等于已经验证更像角色。

## 清晰度

- 环境噪声大时仍可能吃字。GTCRN 和 Silero VAD 会影响弱音、清辅音和句首。
- 10 dB 加噪回归中，塔菲明显改善，爱音的默认档位仍比旧模型有更多错字。测试每条件只有 153 字，不能用小数点差异判断听感。完整分项结果保留在评测记录。
- 除合成语音回归外，增加了两段开源示例中的中文旁白 / 影视对白输入；上游没有逐段录制说明，不一概称为真人麦克风录音。没有用用户本人的麦克风系统地测过。

## 实时通道

- 默认 RVC 路径在 RTX 5060 Ti / DirectML 上验证。0.2.1 的 VB-CABLE 使用 120 ms 包，回归平均每包约 49 ms；Steam 和文件转换保留 200 ms。其他显卡和 CPU 的实时速度未验证。
- VB-CABLE 同一句短句平均延迟约 0.74 s，带噪长句约 0.67 s，刚启动或切换声线可能更高。还需叠加手机 / WO Mic 与 Discord 的延迟；详细范围见 `latency-0.2.1.md`。本次保留完整语音前瞻。
- 与其他大模型推理同时占满显存时会争抢资源，实时测试会失真并可能断流。本次后续验证曾遇到另一个本地模型对比占满显存，未将那段耗时计入正常性能数据。
- Seed-VC 只作为显式启用的实验对照。早期 8 步配置曾在长回录出现断流；不作为默认通话方案，不用其短句结果保证长时间稳定性。
- 引擎一次只服务一个会话。开着实时变声时不能转换文件。
- 0.4.0 默认每 3,000 包刷新实时会话，重开音频流并重置会话状态，模型和后端保持加载。刷新会短暂停顿；真实设备自检以 12 包阈值加速验证，另用单元测试检查 3,000 / 5,000 边界，尚未做数小时真人 Discord 通话测试。不能据此声称已经找到长期音质退化的唯一原因。
- 实验 100 ms 包短句约 0.63 s，但爱音的 47.72 秒带噪回录出现一次播放缺包，默认仍用 120 ms。80 ms 的推理余量更不足，没有作为 GUI 档位。
- 本次 VB-CABLE 部分回录出现采样位置跳变，即使设备与 FIFO 的断流计数为零，整段波形相关性也会下降；120 ms 和实验 100 ms 都遇到过。尚未确认是驱动时钟还是调度问题，因此不把这些低相关性录音当作完整无损回录。详见 `realtime-refresh-startup-0.4.0.md`。

## Discord

- 需要一对虚拟音频设备。Steam 的九次回录已验证；VB-CABLE 重启后已由用户在真实 Discord 通话中确认能传递变声结果，0.2.1 已补做本机定量回录和三位角色各约 48 秒长句测试。默认优先 VB-CABLE，Steam 为备用。
- 本机曾出现朋友先听原声、随后听到变声。现场确认音色强度 100%、变声器采集 WO Mic 并写入 CABLE Input、Discord 采集 CABLE Output；WO Mic 的“设置 → 本地播放”开着。取消该勾选后，播放会话变为非活动、设置保存为关闭，用户让朋友复听确认只剩变声。没有改变模型、强度或缓冲；界面当时显示约 1.0 秒延迟、零播放断流。
- 上述通话确认只证明重复声音消失和通路可用，尚未在真实 Discord 远端系统评测相似度与长期稳定性。

## 界面与安装

- 125% 和 150% 缩放是用 Qt 的缩放参数模拟后看截图检查的。
- Windows 不允许程序把快捷方式固定到任务栏，需要手动右键固定一次。
- 首轮界面 66 项功能检查通过，但退出时发现 QtWidgets 访问冲突；退出前清理全局样式表后的独立多窗口退出检查正常。用户正在实时变声时，重复完整自检会与其争用后端和音频设备，应停止当前实时会话后再跑。
- 新权重、索引和导出图在 `models/local-rvc/`，不随 Git 历史分发。新电脑需要另行复制该文件夹或重新导入；只有源码时会使用原来的兼容声线，界面显示实际模型名。
- 默认 RVC 不安装额外 CUDA 环境；显式启用 Seed-VC 才需要下载其模型及 CUDA 版 PyTorch。全新电脑安装路径尚未完整验证。
- 启动缓存针对已成功校验且属性未变化的本地文件，不能防御能同时修改模型和缓存的本机用户。可用 `VOICE_VERIFY_MODELS=1` 强制完整校验；模型、驱动或运行库变化后会重新准备缓存，首次启动不会达到热缓存启动速度。RVC 图不使用 ORT 序列化缓存，避免 DirectML 融合图重载不兼容。
