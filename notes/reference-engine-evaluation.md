# 0.2.0 模型对照记录

测试日期：2026-11-13。机器：i5-12400F、RTX 5060 Ti 16 GB、Windows 11。

## 最终模型与方法

三位均使用 RVC v2 / 40k，RMVPE、ContentVec 第 12 层与匹配 FAISS 索引。模型和校验值在 [安装清单](installed-rvc-models.json)。灯、塔菲来自用户提供文件；爱音来自 [Wanlau 的固定版本](https://huggingface.co/Wanlau/RVC_BanGDream/tree/7f73089d0c405d605e90d76484b8679ad50fb85a/Anon_v2)。

音色优先：检索比例 0.75，清音特征混合 0.33。通话清晰：检索最多 0.5，清音混合最多 0.15。混合系数越小，保留的原始语言特征越多；它不代表混入同样比例的原始声音。100% 音色强度不混回原始波形。

## 来源更正与对照音

0.1.0 / 0.1.1 的灯和爱音参考音来自第三方 MiMo 合成，之前误称“原始角色对白”。旧相似度不能用作与真实角色配音的比较。此次角色原声改为官方 CM 分离配乐后的录音，塔菲为可追溯直播片段。来源与片段校验值在 [sources.json](../assets/references/sources.json)。

用户提供的“凑企鹅”视频是演唱目标示例，另一个视频是音频导出教学。人声单独分离，记为 `tomori-user-demo`；未核实录制方式，不将其说成已确认的原始角色表演。灯默认目标音域 320 Hz，是为贴近这个用户选择的示例。

额外对照片段：灯 CM 17.5–23 秒；爱音 CM 7.5–11.5 秒和 17–24.5 秒；塔菲同一数据集中另一条直播说话片段（PS5 / 死亡搁浅，1761.858–1766.878 秒）。这些片段没有拼入本次 Seed-VC 提示，但第三方 RVC 的原始训练集不完全已知，不能称为未参与训练的严格盲测。

## 合成语音回归

Windows 慧慧和康康各读 8 句，共 16 句；男声另加风扇、底噪和键盘声至 10 dB SNR。每条件、每角色 153 个字。使用同一条实时分块路径生成 72 条输出，再用 SenseVoice 与已知原句计算字错误率。

基线为 0.1.1：塔菲使用该版音色优先；灯和爱音沿用未在 0.1.1 改动的 0.1.0 输出。这里重新按真实参考评分，不沿用旧的合成参考分数。

| 角色 | 旧版干净女 / 男 / 加噪男 CER | 新 RVC 音色优先 CER |
| --- | --- | --- |
| 高松灯 | 0.0% / 3.9% / 19.0% | 1.3% / 2.6% / 20.3% |
| 永雏塔菲 | 3.3% / 3.3% / 26.8% | 3.3% / 4.6% / 10.5% |
| 千早爱音 | 2.0% / 1.3% / 13.1% | 2.6% / 5.2% / 20.9% |

合计 CER：旧版 8.1%，新 RVC 7.9%。塔菲在强噪声下改善，爱音仍有退步，不能据总分说三位都更清晰。每格仅 153 字，少量错字足以改变几个百分点。

通话清晰档同样渲染 72 条输出，合计 CER 为 6.5%，干净女 / 男 / 加噪男分别为 1.5% / 3.5% / 14.6%。

| 角色 | 通话清晰：女 / 男 / 加噪男 CER |
| --- | --- |
| 高松灯 | 0.0% / 2.6% / 17.0% |
| 永雏塔菲 | 3.3% / 3.9% / 7.8% |
| 千早爱音 | 1.3% / 3.9% / 19.0% |

通话档改善了本次测试的清晰度，但爱音加噪条件仍弱于旧版。不将它表述为全面解决噪声问题。

## 相似度

CAM++ 余弦相似度，按同一批输出、同一种拼接方法重算后取三种输入条件的均值。它不是还原百分比，不代替听感。

| 角色 | 原声参考 旧 → 新 | 额外片段 旧 → 新 |
| --- | --- | --- |
| 高松灯 | 0.428 → 0.430 | 0.425 → 0.428 |
| 永雏塔菲 | 0.520 → 0.552 | 0.460 → 0.487 |
| 千早爱音 | 0.617 → 0.665 | 0.676 → 0.700 |

灯对用户选择的演唱目标：0.558 → 0.592。不同输入的提升并不一致，女声条件略降。与之前 Seed-VC 的短句直接对比中，新灯 RVC 更贴近用户给定演唱目标，而 Seed-VC 更接近另一份动画 CM 参考；两种目标不同，不应混用分数。

## 渲染性能

单进程按 200 ms 包运行，使用 DirectML。各输入条件的平均耗时：灯 62–72 ms，塔菲 59–61 ms，爱音 74–77 ms。全体均值约 67 ms，最高条件的 95 分位约 99 ms。无削顶，停顿段 RMS 低于数值底限。

性能数据来自没有其他大模型占满显存时的完整回归。后续曾出现 LocalAIStudio 的另一个模型对比占满显存，暂停了那一轮额外性能检查，没有将资源争用耗时当作正常吞吐。

原始分项数据见 [evaluation/0.2.0](evaluation/0.2.0)。复现命令：

```powershell
.venv\Scripts\python.exe tools\eval\eval_render.py my-rvc
.run\export-env\Scripts\python.exe tools\eval\eval_asr.py my-rvc
.venv\Scripts\python.exe tools\eval\compare_references.py .run\eval\baseline011 .run\eval\my-rvc --heldout .run\heldout --tomori-demo assets\references\tomori-user-demo.wav --output .run\comparison.json
```

## 虚拟麦克风回录

真实使用 `Speakers (Steam Streaming Microphone)` 发送、`Microphone (Steam Streaming Microphone)` 按 48 kHz 采集，并按正常实时速度提供输入。六次短测试覆盖三位角色的干净和带噪输入，另对三位分别将带噪输入重复五次作长测试。

最初 0.31 秒播放余量的短测试中，爱音出现一次卡顿；初始记录没有区分数据不足与设备回调迟到，不能仅凭它认定根因。随后增加诊断计数，将通话播放余量改为 0.5 秒，设备请求延迟改为 0.15 秒（Steam 实际报告约 0.1596 秒）。

修改后的九次回录均零断流、零 FIFO 丢样、零设备 underflow、无满幅削顶；发送与回录波形相关系数约为 1，信号延迟 0.96–1.12 秒。代价是比原来的 0.77 秒多出播放余量。数据见 `loopback-short.json`、`loopback-long.json`；修改前的失败也保留在 `loopback-before-buffer-fix.json`，不把它隐藏成全程零错误。

```powershell
.venv-gui\Scripts\python.exe tools\eval\loopback.py assets\previews\original.wav .run\noisy-input.wav --output .run\rvc-loopback
.venv-gui\Scripts\python.exe tools\eval\loopback.py .run\noisy-input.wav --repeat 5 --output .run\rvc-loopback-long
```

## 局限

输入仍以合成语音为主，另有两段开源示例的中文旁白 / 影视对白测试。上游未逐段说明原始录制方式，不将它们一概称为真人麦克风录音。没有用用户本人的麦克风系统地验证，也没有由 Discord 远端听众确认听感。自动识别和说话人特征分数不能证明“已经足够像”。

早期 Seed-VC 8 步短句效果较好，但长回录出现过一次断流。它保留为实验对照，未作为这次默认后端；不能把它的 CER 或延迟与最终 RVC 结果混写。
