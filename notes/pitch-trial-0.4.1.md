# 0.4.1：三个角色的 +4 音高试用

日期：2026-11-14。用户给出的塔菲页为 <https://klrvc.com/zh/mxgf/2088>。通过公开页面读取“推理前 / 后”音频区、正文和推荐参数；“推理”在这里表示用训练好的模型转换录音。我们的实时 RVC 已经持续执行推理，不是还没完成的一步训练。

正文参数目前写“变调：0”，推荐 Pitch 0、Index Rate 0.75；没有从正文核验到“所有男生 +4”的统一规则，仍按用户要求提供 +4 试用。页内还有效果处理的描述，示例所用原声和处理链可能与本机不同，不能把网页试听当成本机必然达到的结果。本机使用用户 `Ai塔菲.zip` 中的 `mygf-tf.pth` 和配套索引，检索比例 0.75。网页标 44K，本机检查点实际为 40k；未取得发布页下载文件的哈希，不能仅凭同名证明二者完全相同，运行继续按已验证权重的实际采样率。

## 两种 +4 的差别

RVC 的半音变调是基频乘以 `2^(半音数/12)`，+4 约乘 1.259921。改的是 RVC 波形生成前的 F0，音频时长不变。

此前三个角色使用自动音域匹配：灯 320 Hz、塔菲 429 Hz、爱音 310 Hz，跟随输入的有声音高并平滑缩放。新的“原声 +4”直接把输入 F0 乘 1.259921，替代这一自动匹配；“自动音域再 +4”保留原有匹配后再乘该系数。

以原声中位 150 Hz、强度 100% 为简化例：固定 +4 为 189 Hz；塔菲原自动档约 429 Hz，自动后 +4 约 541 Hz。三位的自动后 +4 目标大致为灯 403 Hz、塔菲 541 Hz、爱音 391 Hz。真实音调起伏和原有 650 Hz 上限仍会影响结果。低于 100% 强度时移调量跟随强度缩放，与原有音色强度行为一致。

GUI 先让三位都用“原声 +4 半音”，并保留另两档供直接比较。选择作用于实时与文件请求，在同一窗口切换角色或自动刷新时保持。程序再次启动仍默认该试用档；`start-gui.cmd --pitch-preset model` / `auto4` 可按另两档启动。原 `models/local-rvc/profiles.json` 没有改动，API 不带音高参数仍按原模型配置工作。

后端参数 `pitch_shift` 指定固定半音，优先于配置中的自动 / 固定设置；`pitch_offset` 在上述结果后再加半音。允许 -24 至 +24 的有限数。相关 Seed-VC 参考路径未实现此控制，GUI 对这些角色禁用选择，当前三套本地 RVC 正常支持。

## 同输入试听

文件在 [assets/pitch-comparisons](../assets/pitch-comparisons/)，全部由本机 0.4.1 文件接口生成，无音频设备播放或 Discord 发送。输入是既有回归集 `m1.wav` 的 5.262 秒合成男声，保存为 `input-male.wav`，不是用户录音。角色 / 强度 100% / 音色优先 / 检索比例 / 权重均相同，仅改音高档。沿用文件模式的 200 ms 包。

三份角色对照的时间顺序一致：

| 时间 | 内容 |
| --- | --- |
| 0.000–5.262 s | 模型默认，原自动音域 |
| 5.862–11.124 s | 原声 +4 半音 |
| 11.724–16.986 s | 自动音域再 +4 |

每段间有 0.6 秒静音，输出保留原幅度，未额外后期处理。文件参数和 SHA-256 见 `manifest.json`。只检查输出有效、非静音、时长一致并提供试听，没有把三档音高差异当作角色相似度改善的证据。

复现：

```powershell
.venv\Scripts\python.exe tools\eval\make_pitch_comparisons.py --backend-url http://127.0.0.1:8766 --input .run\evalset\m1.wav
```
