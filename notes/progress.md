### 测到的结果

16 句话，每个条件每位角色 153 个字。输入本身的字错误率是 0%。

| 配置 | 字错误率 合计 | 女声 | 男声 | 加噪男声 | 相似度 灯 / 塔菲 / 爱音 | 每包耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| A 基线（现状） | 16.3% | 5.0% | 6.8% | 37.0% | 0.607 / 0.646 / 0.651 | 63 毫秒 |
| B 去掉 OpenVoice 校正 | 5.1% | 1.3% | 0.9% | 13.1% | 0.512 / 0.368 / 0.653 | 45 毫秒 |
| C 校正改用整段会话的音色向量 | 9.5% | 1.5% | 4.6% | 22.4% | 0.605 / 0.628 / 0.635 | 64 毫秒 |
| D 同 C，强度 0.6，爱音不校正 | 8.0% | 2.2% | 1.5% | 20.3% | 0.561 / 0.542 / 0.662 | 59 毫秒 |
| E 同 C，并且先校正再补辅音 | 6.4% | 2.2% | 2.0% | 15.0% | 0.606 / 0.526 / 0.627 | 64 毫秒 |
| F 同 E，辅音混入量减半 | 未测 | | | | 0.620 / 0.593 / 0.641 | 65 毫秒 |
| G 同 E，不混入辅音 | 未测 | | | | 0.609 / 0.618 / 0.642 | 64 毫秒 |

结论：

1. 听不清的主要原因是 OpenVoice 音色校正这一步。它对每个一秒窗口单独估计音色向量，相邻的包被处理得不一样。去掉它，字错误率从 16.3% 降到 5.1%。
2. 但塔菲的相似度靠这一步撑着（0.37 对 0.65），灯也受益（0.51 对 0.61），爱音不需要它。
3. 改成用整段会话的音色向量、并且先校正再补辅音（E），清晰度接近不校正，灯的相似度保住了，塔菲掉到 0.53。减少辅音混入（F、G）能把塔菲拉回 0.59 到 0.62，这两组的字错误率还没测。
4. 每个包的接缝处有一次能量下陷：整体掉到 0.83 到 0.86，5 kHz 以上掉到 0.66 到 0.71，每 200 毫秒一次。原因是两次渲染的高频互不相关，线性交叉淡化会损失能量。
5. 加噪条件下即使不校正也有 13% 的字错误率，错在句子中间，像是噪声下的音高和特征提取出错。
